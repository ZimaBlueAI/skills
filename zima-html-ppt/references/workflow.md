# 讲演 deck 工作流 · 方案先行

> 硬规矩：**没有 `deck-plan.md`，不动第一页幻灯片。**
> 用户明确说「直接生成 / 按默认来 / 跳过确认」时，采用默认方向继续，方案仍然要写，
> 只是不停下来等确认。

---

## 1. 意图卡（开工前先答完这七行）

| 项 | 要答清楚的 |
|---|---|
| 受众 | 谁坐在台下，他们已经知道什么，散场后要相信什么、做什么 |
| 场景 | 上台汇报 / 客户路演 / 内训训战 / 发布会 / 异步自读 |
| 时长 | 决定主线页数。**每页 45–90 秒**，`data-min` 之和必须等于承诺时长 |
| 语言与比例 | 默认中文、16:9 全屏；投影环境有没有特殊分辨率 |
| 交付形态 | 单文件 `.html`（默认）；要不要同时保留 `deck.json` 以便改稿 |
| 离线边界 | 图表走 CDN 的 Chart.js 是**唯一联网依赖**；断网现场必须先说清楚 |
| 证据 | 每个数字的来源与口径日期；核不了的主张标 `[估]` 或 `[N/A]` |

**离线现场**：如果用户说场地断网，把 Chart.js 换成本地文件或去掉图表，
并在交付说明里写明这一改动——不要嘴上答应离线、手上留 CDN。

---

## 2. 三个方向 · 选择卡

主题宽泛时（"讲讲我们的 AI 战略"），先给三张卡再动手，并**明确推荐一个默认**：

- **`1a` 说服型** —— 一个冲突、一条变化、一句结论。适合客户路演、对外发布。
- **`2b` 决策型** —— 现状、选项、权衡、建议、下一步。适合向上汇报、董事会前置沟通。
- **`3c` 训战型** —— 概念、机制、示例、动手、收束。适合内训课件、训战材料。

主题已经很具体时（"把这份季度复盘讲成 20 分钟"）跳过选择卡，直接给一个方案。

---

## 3. `deck-plan.md`（source-grounded 资料稿）

用 `templates/deck-plan-template.md`。逐页计划表里最关键的一列是**视觉所有者**：

> 一条信息只由一个层级负责——标题、图表、卡片、正文、逐字稿，**四选一**。
> 屏幕上的字和嘴里念的话不许是同一句；标题已经说完的结论，正文不要再复述一遍。

这是全套规则里最能救场的一条：它同时治好"页面话太多"和"演讲者只会念屏幕"。

---

## 4. 内容 → 组件映射

| 内容形态 | 首选 | 避免 |
|---|---|---|
| 趋势、量级、占比 | `chart`（bar / line / area） | 把所有数字写进句子里 |
| 三到五个并列要点 | `cards` 或 `list` | 十几行 bullet 铺满一页 |
| 规格、报价、功能矩阵 | `table` | 散落的文本框 |
| 两个方案对比 | `layout: compare` + 两栏 `cards` | 一栏里塞两套逻辑 |
| 图 + 解读 | `layout: split`（左图右论） | 图和字上下堆成两半 |
| 关键单点数字 | `metrics`（大号 + `count` 滚动） | 小字号 KPI 卡片墙 |
| 相对强弱、完成度 | `bars` | 用饼图表达"谁比谁大" |
| 命令行、代码、配置 | `term` | 截图当代码贴 |
| 引用他人原话 | `quote` + `cite` | 用自己的话转述竞品评价 |
| 收尾金句、行动号召 | `layout: closing` + `bigline` | 再来一页密密麻麻的总结 |

**至少要有一个"数字砸下来"的时刻**——`metrics` 的滚动或 `bars` 的填充，
落在整场最想让人记住的那一页。动效为了解释变化，不为了看起来在动。

---

## 5. 页数与配额

```
承诺时长（分钟） ÷ 1.2 ≈ 主线页数上限
```

- 12–25 页是舒适区，低于 12 页说明拆得不够，高于 25 页台上一定超时。
- 封面 1–2 分钟、图表页 3–5 分钟、过渡页 0.5–1 分钟、收尾 1 分钟。
- `data-min` 之和 = 承诺时长。校验脚本会把总配额打进 `stats.totalMinutes`，自己对一遍。

## 6. 两条构建路线

| | 手写 starter | 脚本构建 |
|---|---|---|
| 起点 | 复制 `templates/zima-ppt-starter.html` | 写 `deck.json` |
| 适合 | 一次性、版式要高度定制的场合 | 要反复改稿、要机器校验、要留档 |
| 改稿 | 人重读 HTML 手改 | `extract` → 改 JSON → `build` |
| 身份 | 无 | `deckId` 全程保持 |
| 校验 | `validate deck.html`（只跑 HTML 层闸门） | `validate deck.json` + build 时自动跑全套 |

**默认走脚本构建**；用户明确要"这一页我要个特殊版式"时，用 `html` 逃生口塞进那一块，
或整份改走手写路线——但要在交付说明里讲明代价（下一版改稿要人重读 HTML）。

```bash
# 新建（只在这一次铸 deckId）
python scripts/zima_deck.py build deck.json \
  --output output/2026-07-27-xxx-deck.html \
  --new-document --write-back \
  --report reports/deck-validation.json

# 改稿（从原文件继承身份，产出 sibling，绝不原地覆盖）
python scripts/zima_deck.py extract output/2026-07-27-xxx-deck.html --output deck.json
#   …改 deck.json…
python scripts/zima_deck.py build deck.json \
  --identity-source output/2026-07-27-xxx-deck.html \
  --output output/2026-07-27-xxx-deck.updated.html \
  --report reports/deck-validation.json
```

> macOS / Linux 上把 `python` 换成 `python3`。脚本只用标准库，不联网。

## 7. 浏览器验收（脚本过了 ≠ 验收过了）

至少实际打开确认这六条，任何一条没做就在交付说明里写 `missing evidence`：

- [ ] 封面 + 信息最密的一页 + 带图表的一页，文字无裁切、无越界、无重叠。
- [ ] `← →` / 空格翻页正常，`Home` / `End` 正常，刷新后停在同一页（hash 生效）。
- [ ] 按 **S** 弹出演讲者窗口：逐字稿在、橙色高亮在、议程列表高亮当前页、计时在走。
- [ ] 按 **F** 全屏，投影比例下不出横向滚动条。
- [ ] 图表渲染出来了（断网时 Chart.js 会失败——离线场次要提前验）。
- [ ] 数字滚动、条形填充只在进入该页时各跑一次，没有无限循环。

命令行只能证明结构和签名，证明不了"看起来对"。这一节是人的活。
