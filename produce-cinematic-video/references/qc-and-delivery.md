## 建立验收矩阵

不要用一个“通过”覆盖所有问题。为每个 deliverable 建立矩阵：

| 维度 | 负责人 | 方法 | 证据 | 状态 |
|---|---|---|---|---|
| 技术 | 后期/QC | 自动扫描 + 全片播放 | 报告、时间码 | pass/fail/waived |
| 故事/表演 | 导演/剪辑 | 实时审片 | notes |  |
| 事实/伦理 | 制片/编辑/专家 | source map 核查 | 引用、批准 |  |
| 连续性/动画 | 剪辑/动画/VFX | 逐镜/逐帧 | acceptance log |  |
| 声音 | 声音/混音 | 仪表 + 目标环境试听 | mix report |  |
| 色彩 | 调色/QC | 管线与目标显示检查 | scopes、still |  |
| 可访问性 | 字幕/QA/用户测试 | 文本与播放检查 | caption report |  |
| 权利/营销 | 制片/品牌/法务 | 清单和证据 | release/claim map |  |

Waiver 必须写明问题、影响、批准人和日期，不能静默忽略。

## 运行技术质检

先运行 `scripts/validate_project.py`，再运行 `scripts/qc_media.py`。自动脚本仅筛查，不替代完整播放。

检查：

- 文件可打开、时长、起始时间码、分辨率、像素宽高比、显示宽高比；
- 平均/实际帧率、扫描方式、旋转、掉帧、重复帧和速度变化；
- codec、profile、level、bit depth、pixel format、色域、transfer 和 matrix；
- 黑场、冻帧、闪帧、离线帧、损坏帧和意外静音；
- 音轨数量、声道布局、采样率、相位、响度、true peak 和头尾；
- 标题安全区、字幕、图形、语言、拼写和版本标识；
- 文件名、metadata、checksum 和病毒/恶意内容策略（若交付要求）。

在目标播放器、设备或场地重新打开最终文件，从头到尾实时播放。抽帧无法发现运动、节奏、同步、帧序错误和许多编码问题。

## 审查故事与表演

- 编辑命题是否在结尾成立？
- 场景/段落是否发生了状态变化？
- 信息是否在观众需要时出现，是否重复解释？
- 关键表演、反应、笑点、沉默和余韵是否被保护？
- 观众是否能理解人物、空间、目标、障碍、因果和结果？
- 节奏是否有结构变化，而非全程同密度？
- 开头承诺和结尾兑现是否一致？
- 删除任一镜头会损失什么？答不出时重新评估。

## 审查事实与生成内容

- 每个可核查主张是否指向来源和适用条件？
- 引语、采访和档案是否保留上下文、时间与来源？
- 蒙太奇是否制造错误因果、顺序、地点或人物反应？
- 模拟、重演、生成图像/声音/视频是否有准确、可见的披露？
- 生成的人、产品、机制或事件是否会被误认成事实证据？
- 统计、姓名、职位、日期、地图、单位和翻译是否复核？
- 未成年人、创伤、隐私和敏感身份是否通过更高等级审核？

科学或产品证明同时检查对象数量、尺度、连续路径、接触、支撑、能量来源、损耗和最终结果。

## 审查画面与连续性

- 镜头内是否存在手、脸、文字、边缘、反射、遮挡或对象增减异常？
- 人物身份、服装、惯用手、道具和伤痕是否一致？
- 轴线、视线、屏幕方向、地理、动作和重心是否可读？
- 光源、阴影、色温、曝光、镜头感、景深和颗粒是否连续？
- 变速、稳定、插帧、重构和 VFX 是否产生重影、扭曲或瞬移？
- 色彩管理是否正确解释素材；没有把错误色域转换当风格？
- 高光、暗部、饱和和合法电平是否符合交付环境？
- 图形、字幕和品牌元素是否对齐、安全且不挡关键动作？

动画额外检查 pose、silhouette、arcs、spacing、接触、hold、口型和次级运动。

## 审查声音

- 对白、采访和旁白是否可懂且语气真实？
- room tone、ambience、距离、混响和噪声底是否连续？
- 接触、脚步、机械和环境是否与可见触发同步？
- 音乐是否遮挡信息、抢夺表演或破坏事实观察？
- 静默是否有意，是否遗漏关键提示？
- 响度、true peak、相位、声道、采样率和 M&E 是否符合 delivery profile？
- 耳机、小扬声器、单声道折叠和目标环境是否试听？

## 审查字幕与可访问性

- transcript/caption 是否逐句对应最终声音，而非旧版脚本？
- 人名、术语、数字、单位、方言和翻译是否校对？
- 每条字幕是否有足够阅读时间、合理断句和不遮挡的区域？
- 说话人、画外声音、关键音效和音乐信息是否按规范标注？
- 烧录字幕和 sidecar 是否帧率/时间基一致？
- 颜色、字号、对比和安全区是否适配目标屏幕与平台 UI？
- 重要视觉信息是否需要音频描述或口头等价？
- 仅靠颜色、声音或快速闪动传递的信息是否有替代方式？
- 闪光、运动或声音敏感内容是否需要警示或替代版？

## 审查营销与权利

- 产品、性能、价格、疗效、比较、见证和稀缺主张是否有证据？
- 音乐、档案、字体、商标、人物、地点、艺术品和生成参考是否有权利记录？
- 授权是否覆盖地区、期限、媒介、广告、剪辑和衍生版本？
- 标题、封面、CTA 与内容是否一致，不构成误导？
- 合成内容、赞助、广告和非典型结果是否披露？
- 版本是否符合当前官方平台规格与政策？

高风险项不要由模型自行“法律通过”；标记并交给有资格的人。

## 建立交付包

按合同选择，不要默认全部输出：

### 审阅

- 带 timecode/burn-in 的低码率 review；
- 版本、日期、watermark 和 review notes；
- 明确“非母版/非发布”。

### 发行

- clean master 和 captioned master；
- 按配置的 codec、raster、fps、color、audio 和 loudness 导出；
- captions/subtitles、thumbnail/cover 和 platform metadata。

### 后期交换

- mezzanine master；
- 带 handles 的 picture/reference；
- EDL、FCPXML、AAF 或项目文件；
- OMF/AAF 或对齐 stems；
- LUT/CDL/色彩说明、字体与图形依赖。

### 归档与审计

- camera-original manifest、checksums 和 proxy map；
- final edit plan、project manifest、cue sheet、QC report；
- transcripts、rights/releases/credits；
- generated-media provenance、prompts、task records 和 disclosures；
- retrospective 与已批准 waiver。

所有 stem 从同一零点导出。重新导入叠加，确认可还原最终混音。打开每个交付文件并核对 checksum。

## 编写 QC 报告

报告至少包含：

- 项目、版本、文件、checksum、测试日期和环境；
- 交付 profile 与预期值；
- 自动检查结果及原始测量；
- 人工审看维度、观察和时间码；
- issue severity：blocker、major、minor、note；
- 修复、复测、waiver 和批准；
- 未覆盖范围和工具限制；
- 最终结论：pass、conditional pass 或 fail。

不要把“脚本无报错”写成“内容通过”。不要删除失败记录；关闭 issue 时保留前后证据。
