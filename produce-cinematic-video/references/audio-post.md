## 先做声音叙事

把声音分成六种职能：

1. **信息：** 对白、采访、旁白、关键动作声；
2. **空间：** room tone、ambience、距离、混响、遮挡；
3. **身体：** 呼吸、衣物、脚步、接触、重量和材质；
4. **结构：** 声音桥、段落边界、riser、hit、静默；
5. **主观：** 记忆、焦虑、耳鸣、内部声音和失真；
6. **音乐：** 情绪、速度、时代、文化和品牌记忆。

先建立可理解、可信的声场，再加情绪。完全无底声通常像错误；刻意静默必须有进入、持续和退出的设计。

## 管理 cue

复制 `assets/audio-cue-sheet.template.csv`。每条 cue 记录：

- 稳定 ID、场景、触发时间码和叙事功能；
- source、rights、版本、长度和格式；
- 画面内/画面外、主观/客观、距离与空间；
- prompt/model/task 或录音信息；
- sync acceptance、mix status 和交付 stem。

用 scene/shot/cue ID 命名。编辑使用无损 WAV/BWF；轻量审阅文件可以压缩，但不要把压缩审阅件当母版。

## 对白采访与旁白

1. 同步双系统录音并保留原时间码。
2. 先做内容编辑，再做去噪、均衡、动态和精修。
3. 保留自然呼吸、停顿和空间；不要把每个间隙都压到广播腔。
4. 用 room tone、交叉淡化和一致噪声底隐藏句内编辑。
5. 逐句检查指代、语气、限定条件和上下文；纪录片不得通过拼接改变原意。
6. ADR 先匹配表演、距离、角度和空间，再匹配频谱。
7. 旁白先用 scratch track 验证结构和时长，文字锁定后再正式录音。

对白可懂度优先于音乐冲击。噪声处理宁可保留轻微真实底噪，也不要产生水下、金属或断续伪影。

## TTS 与声音克隆

- 获取说话者明确同意并记录允许的用途、期限、语言和撤回方式。
- 不克隆公众人物、未授权个人、未成年人或敏感对象来表达其未说内容。
- 先录人类 scratch track，确定意图、听者、距离、速度、年龄感和情绪变化。
- 每轮只改变一个变量，生成 A/B 并盲听；保留选中版本、提示、参数和理由。
- 对合成声音做受众可理解的披露，尤其是纪录、新闻、见证和广告内容。
- 给所有口语内容提供 transcript/caption；关键声音信息提供视觉等价。

使用 IndexTTS2 做本地情感声音克隆时，同时读取 `references/index-tts2.md`。把音色、情感、台词、速度和空间视为不同变量：音色参考负责角色身份，独立情感参考/向量/文字负责表演方向，最终空间由后期完成。不要用强情感掩盖读音、节奏或角色不一致。

IndexTTS2 的四种情感控制方式互斥。文本情感以较低 alpha 起步；随机采样默认关闭，因为会降低克隆稳定性。每个正式 take 都保留 consent record、输入/输出 checksum、情感模式、alpha、模型/代码版本、验收者与披露说明。

使用 Qwen3-TTS 时同时读取 `references/qwen3-tts.md`。根据任务选择模型：VoiceDesign 负责从属性描述创造新音色，CustomVoice 负责官方预置 speaker 与 instruction，Base 负责经授权的参考声音克隆。不要用 VoiceDesign 提示去点名模仿真实人物；不要因“音色是生成的”而省略合成披露。声音设计提示先写角色功能、说话对象、距离、节奏和情绪变化，再写音色属性，避免只堆“温暖、专业、电影感”。

IndexTTS2 与 Qwen3-TTS 都应使用各自隔离的 Python/模型环境。按任务和已配置模型能力路由，不以某个包可导入就宣称全部模型已安装。初始 `.env.local` 只列实际启用 provider 的必填项；默认设备策略是 CUDA → XPU → Apple MPS → CPU 的 GPU 优先自动选择，设备、dtype、attention 和采样参数只有排错或经测试的性能策略才覆盖。用各自的 `doctor --runtime-import` 核对实际设备，不以操作系统检测到 GPU 代替专用 Python 的 Torch 检查。

低配设备需要本地克隆时读取 `references/lightweight-tts.md`。Pocket TTS 是 CPU 优先且当前不支持中文，只能用于其官方列出的欧洲语言；LuxTTS 可走低显存 GPU 或 CPU 并输出 48 kHz，但上游没有语言矩阵，正式 take 前必须通过该语言的人工试听和 ASR 回验。两者都只接受本地 reference、必须带 consent record，并独立于 Qwen3-TTS/IndexTTS2 环境。不要在角色声音已批准后为了省算力静默换引擎。

## 生成音乐与音效

使用 Suno、Udio、ElevenLabs 或其他生成平台时，同时读取 `references/generated-music-and-sfx.md`，并复制 `assets/audio-generation-brief.template.md`。先用 cue 的剧情功能、情绪弧、同步图、转场和对白空间约束提示词，再写类型、乐器与音色；不要把“cinematic、epic、emotional”当完整声音设计。

生成器负责候选，NLE/DAW 负责逐帧同步、结构剪辑、空间、频谱、动态、响度与交付。音乐与音效分别生成时要共享同一个 sync map，避免在转折处同时堆满鼓点、impact、riser 和对白。

## 环境 Foley 与效果

- 能录真实 Foley 和环境时优先录，尤其是材料、机械、脚步和教育实验。
- 环境底跨剪辑连续，并随镜头距离、房间和门窗变化。
- 接触声从可见接触开始；预备、撞击、共振和衰减共同决定重量。
- 机械循环随速度变化并随机制停止；不要让循环跨过画面中的停机。
- whoosh、riser、hit 和 sub drop 只给结构与动作盖章，不用于掩盖弱剪辑。
- AI 同步音频逐事件检查；“有声音”不等于声源、时间和材质正确。

## 音乐

先确认版权、地区、期限、媒介、广告使用和 Content ID 风险。

- 选曲先看结构、短句、速度和动态，不只看情绪标签。
- 给对白和关键同期声留频谱与动态空间。
- 用音乐进入、退出、抽空和重新进入塑造章节。
- 不要求每个切点踩拍；画内动作、字幕和声音也可承接节拍。
- 高潮前静默或 breakdown 只有在结构需要时使用，不作为固定套路。
- 生成音乐前取得用户许可并记录模型、权利和平台检测风险。

## 音源分离与声画同步

同时读取 `references/audio-separation-and-sync.md`。当混音素材需要换语言配音、对白清理、M&E 回填或去混响时，优先使用已配置的本地 GPT-SoVITS/UVR5：

```text
python <skill-dir>/scripts/gpt_sovits_uvr5.py list-models
python <skill-dir>/scripts/gpt_sovits_uvr5.py separate source.wav --model HP2_all_vocals --output-dir stems
```

先用 `doctor --runtime-import` 记录实际设备；`device=auto` 在该隔离运行时可见 CUDA 时优先 GPU。不同 UVR5 模型解决不同问题，先做短片段盲听，不把一次分离当作干净母带。没有可用 GPT-SoVITS 环境时，Demucs 可作为替代：`demucs --two-stems=vocals -n htdemucs -d cuda source.wav`。

画面中有人开口时，用 `scripts/av_sync_align.py` 产生全局偏移候选和可见嘴部活动窗口，再结合转写/强制对齐和逐句实时播放确认。嘴部运动相关性不能识别音素，也不能替代动画口型或人工验收。实战要点：

- **选 BGM 段先扫能量曲线**（10s 窗 volumedetect 全片一遍，候选段再 1s 窗细扫）：
  盲选窗口很容易把乐句间歇或音乐自然终止点框进正片中段。**让视频结尾对准源音乐的
  自然收束**是最省事的高级感来源；源音乐终章前的短暂戏剧性停顿若恰好落在留白位，
  是加分项，不要修。
- **场景音效层**：每个剪辑片段用自己时间对齐的伴奏 stem 垫底（对白已剥离，
  音量可以从"防串词"的 10–15% 提到正常垫底电平），换语言配音压上后场景仍然鲜活。
- 分离后的 stem 与新配音、新 BGM 分层混音时，遵守本文响度与 duck 规范。
- 用 `scripts/mix_stems.py` 记录每条 stem 的增益、duck、响度目标与输出 provenance；不要只凭播放器滑块留下不可复现的混音。

## 剪辑与混音

建议顺序：

1. 对白/采访/旁白；
2. room tone 与连续环境；
3. Foley 和关键动作；
4. 设计效果与主观声；
5. 音乐；
6. 自动化、总线和母版限制。

使用 J/L cut 连接场景和思想。Ducking 的深度、attack 和 release 按语言、音乐密度和情绪调节；不要把固定 -9 dB 当答案。用响度自动化之外的编曲、EQ 和声像为对白让位。

常规视频后期以 48 kHz 为项目基准；位深、声道布局和母版格式由交付合同决定。保留 dialogue、music、effects、ambience，以及需要时的 M&E。

## 响度与交付

从用户配置中的 delivery profile 读取 integrated loudness、true peak、声道、采样率和 codec。合同、广播机构、影院校准或平台官方规范优先。

不要把网络常见工作目标（如约 -14 LUFS）套到广播、电影或所有平台；广播地区常见 -23 LUFS 或 -24 LKFS 体系，影院则依赖校准声压和混音环境。先确认交付标准，再测量。

进行响度归一时优先两遍测量。限制器不能修复对白不清、动态设计错误或单个刺耳瞬态。生成审阅件后重新测量，因为编码会改变 true peak。

## 声音验收

- 台词、采访、旁白在目标设备和合理音量下是否可懂？
- 语气、限定词、停顿和情绪是否仍真实？
- room tone、环境、透视和混响是否跨剪辑连续？
- 每个可见接触、机制和脚步是否同步且材质可信？
- 音乐是否让位于信息和关键同期声？
- 刻意静默是否可辨认，是否误伤关键提示？
- 响度、true peak、相位、声道、采样率和头尾是否符合 profile？
- 单声道折叠、小扬声器、耳机和目标场地是否检查？
- transcript、caption、声音指示和音频描述是否齐全？
- stems 是否从同一起点导出，叠加后能还原全混？
