## 先判断能否生成

在调用提供方前回答：

1. 用户是否授权把相关素材上传到该提供方？
2. 人物、声音、品牌、档案、未成年人和私人空间是否有使用许可？
3. 生成内容会不会被误认为实拍证据、真实见证、真实产品表现或真实人物陈述？
4. 发行方、平台、委托合同和当地规则是否要求披露或禁止某类合成内容？
5. 预算、模型、能力、数据保留政策和输出权利是否已配置并确认？
6. 能否用剪辑、补拍、确定性动画、传统 VFX 或静帧解决？

任何事实、同意、隐私、权利或预算项不清楚时，停止远程调用并请求决定。不要把“技术上能做”当作“允许做”。

## 选择最低风险媒介

按以下顺序搜索解法：

1. 改入出点、使用 alternate、改变顺序、留白、省略或声音桥；
2. 重构画面、裁切、稳定、变速、插帧、常规合成或局部修复；
3. 使用实拍 pickup、Foley、ADR、旁白或道具插入；
4. 使用确定性 2D/3D/物理动画；
5. 生成静帧并做有限运动；
6. 图生视频、首尾帧过渡、视频延长或纯生成视频。

选择标准包括：事实风险、可控性、连续性、成本、时间、可回退性和观众价值。便宜并不自动优先，真实和可验收优先。

该顺序用于提出风险更低的方案，不授权把一种媒介冒充另一种媒介。用户明确要求 Seedance 类模型视频时，先读取 `references/seedance-video.md`，在已配置 provider 上生成真实模型镜头；HTML/Pillow/OpenCV/NLE 动效只能标成 animatic、预览或后期合成。用户要求 GPT Image 2 或 Gemini Nano Banana 时读取 `references/generative-image-providers.md`。

## 按能力选择提供方

读取用户配置，不按厂商名猜能力。只使用明确声明的 capability：

- `text_to_image`
- `image_edit`
- `inpaint`
- `outpaint`
- `text_to_video`
- `image_to_video`
- `first_last_frame`
- `video_extend`
- `reference_identity`
- `synchronized_audio`
- `tts`
- `voice_design`
- `sound_effects`
- `music`

调用前核对当前官方文档中的输入限制、分辨率、时长、参考图数量、首尾帧与参考图是否互斥、内容政策、数据保留、价格和异步任务协议。把核对日期与实际估价写入 gap。静态配置仅表示用户偏好，不保证服务能力没有变化。

## 锁定连续性

先复制 `assets/continuity-sheet.template.md`。将连续性分为不变量与可变量：

- **人物：** 面部结构、年龄、肤色、发型、服装、比例、惯用手、表演状态；
- **道具：** 数量、材质、损伤、内容物、方向、握持点和前后状态；
- **空间：** 几何、地平线、入口、相对位置、尺度、接触面和阴影；
- **摄影：** 画幅、景别、机位高度、镜头感、景深、运动、曝光、色温和颗粒；
- **时间：** 时段、天气、光线、湿度、污渍、伤痕和叙事阶段；
- **声音：** 距离、房间、底噪、动作源、混响和声画同步。

只修解决问题的最小区域。局部错误用 inpaint；取景不够用 outpaint；结构或机位全错时重做参考帧；角色跨镜头失真时先做批准的 reference sheet，再继续视频。

把修复帧与前后镜头并排、差分或 50% 叠加检查。验证轮廓、视线、屏幕方向、接触、数量、阴影、透视和色温。

## 约束物理过程

使用 `assets/physical-shot-card.template.md` 定义：

- 对象及数量、尺度参照；
- 固定件和运动件；
- 初始位置、速度和状态；
- 力、能量或驱动源；
- 接触、支撑、约束和连续路径；
- 摩擦、阻尼、损耗和碰撞结果；
- 最终状态和可测结果；
- 镜头为何能证明过程；
- 同步声音及其可见触发。

先让一个对象走完完整闭合路径，再扩展到群体。先原型化送料、碰撞、门、轨道、杠杆或其他机制，再追求材质和氛围。数量守恒、碰撞、参数变化或重复实验是核心时，切换到确定性动画；不要无限提示词迭代。

## 编写镜头契约

把提示词写成可验收的镜头契约，而不是形容词堆叠。建议顺序：

1. 镜头目的与身份；
2. 必须保持不变的参考；
3. 初始状态；
4. 按时间展开的动作、接触与因果；
5. 摄影机位置、镜头、运动和限制；
6. 最终状态；
7. 同步声音；
8. 禁止出现的可观察偏差。

使用正向边界，例如“球始终位于两条轨道壁之间”“每个可见物体都有支撑”“最终容器保留全部对象”。少写“电影感”“高级”“丝滑运镜”等不可验收词。

对人物表演写对象、意图、对象关系、距离、节拍和变化；不要只写“开心”“悲伤”。对镜头运动写心理和叙事目的；无目的时锁机。

## 使用首尾帧

给两帧不同任务：

- 首帧证明人物、装置、空间和动作能够从正确状态开始；
- 尾帧证明叙事、物理、构图或转场结果可以验收。

两端先统一画幅、构图逻辑、角色身份、色彩和光线。若提供方不允许首尾帧与参考图同时使用，先在图像阶段解决一致性，不要隐式违反 API 契约。

生成转场只在变形、穿越、时间跃迁或不可能连续运动具有叙事意义时使用。仅为掩盖选材问题时，回到 shot manifest。

保留可供剪辑的 handles；具体帧数由帧率、动作和转场决定。检查首尾接缝时同时看运动、光流、曝光和声音。

## 单变量迭代

维护版本账本：

| 字段 | 内容 |
|---|---|
| version | 稳定版本号 |
| hypothesis | 本轮只改变的一个结构或运动假设 |
| preserved | 从上一批准版冻结的内容 |
| result | 可观察结果和时间码 |
| deviation | 剩余偏差与严重度 |
| decision | 接受、局部修、重做或换媒介 |
| cost | 估算与实际成本 |

先解决结构、路径、数量和表演，再解决材质、细节和风格。后续版本退化时立即回到最后批准版。相同核心偏差连续出现三次时结束当前生成分支，换提示结构、参考、提供方、实拍或确定性媒介。

保存失败输出及原因，但不要把失败片段混入可用素材目录。

## 整合与验收

生成后立即验收，不等最终 QC：

- 逐帧查看接触、手、脸、文字、边缘、遮挡和突然增减的对象；
- 实时播放检查节奏、惯性、重量、口型、同步和闪变；
- 与前后镜头并排检查色彩、颗粒、镜头、运动和环境声；
- 核对事实、披露、权利、预算与 gap acceptance；
- 把批准文件路径和实际时长写回 edit plan；
- 不让插帧、稳定或变速制造新的瞬移、重影或物理错误。

对于产品演示、科学过程或纪录片，验收者必须能指出画面中的真实证据，而不是只说“看起来合理”。

## 保留溯源

为每个生成资产记录：

- asset/shot/gap ID；
- provider、adapter、model 和任务 ID；
- prompt、negative constraints、seed/parameters（若提供）；
- 输入参考及其权利；
- 创建时间、成本、版本和操作者；
- 合成类型与披露文字；
- 接受/拒绝状态、时间码和原因；
- 输出 checksum。

不要记录密钥。不要把提供方返回的临时下载 URL 当永久来源；下载后校验并保存任务记录。
