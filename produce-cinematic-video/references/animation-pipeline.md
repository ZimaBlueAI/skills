# 动画制作流水线（七职能 Agent 编排）

一句自然语言即可启动完整动画制作；专业剧本/分镜表是更高优先级约束（见 director-modes.md
优先级链）。七个职能各有协议卡（`agents/animation/01–07`），执行到某工位时**必读该卡全文**。
具备子任务能力的多 Agent 宿主可把每张卡作为独立 subagent 的系统提示；
单 Agent 宿主则按 DAG 顺序逐工位切换角色执行——两种方式产物契约完全相同。

## DAG

```
[编剧] ──┬─→ [角色设计师] ──┐
         ├─→ [场景设计师] ──┼─→ [分镜师] ─→ [音效总监] ─→ [总导演及剪辑师]
         └─→ [道具设计师] ──┘         （分镜师输出的时间线是音效总监的输入）
```

- 三个设计工位**可并行**（多 Agent 宿主并发派发；单 Agent 顺序执行）
- 每条边是一次**握手**：下游开工前验收上游工件（缺→打回，不缺→签收进 project.json）
- 世界指纹由角色设计师定稿画风派生、场景设计师登记，之后对三个设计工位与分镜师全局生效

## 项目状态（单一事实源）

`project.json`（schema：`schemas/animation-project.schema.json`；模板：
`assets/animation-project.template.json`）。铁律：

1. **任何工件生成后立即登记**（路径、状态、成本、指纹引用），不存在"文件在磁盘但状态未知"
2. 每个节点状态机：`pending → running → review → approved | rework`
3. **中断/修改/推进协议**：
   - 用户可在任意时刻中断；恢复时读 project.json，只跑非 approved 节点
   - 用户修改任一中间产物（如换一张场景图、改一句台词）→ 该节点重置 review，
     其**下游受影响节点自动标 `stale`**（依赖表见 schema 的 depends_on），
     stale 节点复跑，approved 且未受影响的节点原样复用——改一个细节不重跑全片
   - 修改记录追加进 `history[]`（谁改的/改了什么/波及哪些节点）
4. 成本台账：每次付费生成写 `cost_log[]`（工位、provider、量、金额），
   累计超预算（默认 ¥30，可在 project.json 设定）先停下问用户

## 可视化 Dashboard（每次状态变更后重新生成）

`python scripts/pipeline_dashboard.py <project.json>` → 项目根 `dashboard.html`：

- **SVG DAG**：七节点按状态着色（灰 pending / 蓝 running / 黄 review / 绿 approved /
  红 rework / 橙 stale），边显示握手状态；纯内联 SVG 无外部依赖
- **工位卡片**：每工位一张卡——图（Model Sheet/场景/首帧缩略）、音频 `<audio controls>`、
  视频 `<video controls>`，全部相对路径引用工件原文件；状态徽标、成本、最近一次变更
- **实时更新**：页面 `<meta refresh>` 5s 自刷新；流水线每次写 project.json 后必须
  重新运行 dashboard 生成器（工位协议的收尾步骤）
- 交付时 dashboard.html 一并交付——它就是全片的可视化生产档案

## 工位间对齐要点（跨卡规则）

- **指纹接力**：角色（视觉+声音）指纹由 02 定稿 → 03/04 只读引用 → 05 逐镜注入 →
  07 逐镜比对。任何工位不得擅改上游指纹；需要改 → 打回上游走 rework
- **状态量对齐**：道具/角色的剧情状态变化（07 类指纹之"动作状态"）在编剧场次表登记，
  道具设计师建状态机，分镜师按场取态，总导演验收连续性
- **物理铁律全局生效**：seedance-video.md 四条物理提示词铁律对 05 强制；
  编剧在 01 就用"状态A→状态B"写动作，从源头规避
- **声音三层规范**：对白清晰度优先，音乐按对白动态 duck，环境声保持空间感；响度目标由发行平台与项目 profile 决定（06/07 共同持有）
- **导演审片优先于技术质检**：07 的审片报告是交付前置条件，qc_media 只是第二道闸

## 戏剧性共同法则（visual-skills/Murch 谱系，01/05/07 共同持有）

- **场景五要素**：主角欲望 + 障碍 + 空间几何 + 视线控制 + 剪辑节奏——缺一不成场（01 写场时自查）
- **三功能规则**：每个镜头必须改变情绪、推进行动或增加压力三者其一，否则删（05 排镜、07 装配各查一遍）
- **细节法则**：每镜提示词带三个物理细节——环境压力（风/雨/尘/光变）、身体微动作（攥拳/呼吸/眯眼）、
  声音或视觉母题回响；"没有身体的情绪渲染不出来"
- **剪辑裁决顺序**：先守情感与故事，再看节奏、视线、屏幕方向和空间连续性；发生冲突时记录取舍依据
- **禁用占位词**：cinematic / epic / stunning / masterpiece / beautiful / 高级感 / 电影感 / 丝滑——
  这些词出现即说明细节缺失，回去补三个物理细节

## 启动模板（用户一句话 → 开工）

```text
用户：「把这个故事做成 1 分钟动画：<故事>」
→ 建项目目录（characters/ scenes/ props/ shots/ audio/ deliverables/ + project.json）
→ [编剧] 开工 …… 每工位完成即更新 dashboard，review 节点呈用户绿/黄/红
```
