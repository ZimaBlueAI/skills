# Grok Bot usage

Grok Bot has a persistent cloud computer with a browser, filesystem and terminal; access to a particular file, connector or executable must still be checked in the active environment. Ask the Bot to save the content of `SKILL.md` and the relevant references as a private skill; ask for it by name. The documentation does not establish that cloning a repository automatically installs skills into Bot, so verify the saved skill and its references inside the Bot.

Grok Bot is distinct from Grok Imagine and the xAI API. The skill can edit with locally available tools; no subscription API, paid generation, automatic upload or scheduler is assumed. A connector or login may be needed to read a user's source files. Request user action for credentials; never collect passwords in chat. If a tool or attachment isn't accessible, stop the dependent step and report it.

That example is an independent third-party Bot; this playbook is independently written and does not require that Bot or impose its approval rules on users.

Additional reference: [Video Edit Desk marketplace listing](https://x.ai/bot/marketplace/bots/best-video-editor) describes keeping a media report, shot map and cut log alongside source files. Apply this as a portable practice, not as a claim that this skill uses or includes that Bot. [Computer and apps](https://docs.x.ai/grok-bot/computer-and-apps) notes that some computer updates remove installed packages: recheck tools each run. A [community discussion](https://www.reddit.com/r/aivideomaking/comments/1wvw95d/ai_video_tools_are_filling_the_gap_in_post/) reports repetitive shots and monotonous cut rhythm as possible failures; treat those as anecdotal risks and inspect the actual edit rather than as proven system limitations.
